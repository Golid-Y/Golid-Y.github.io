C3 · 独立站与 AI 协作

项目概览

2026 年 7 月下旬，我开始为求职整理个人作品集。普通简历可以列出账号、实习和校园经历，却很难同时交代过程、证据和我在团队中的具体职责。我决定做一个独立站，让招聘方可以快速浏览，也能在感兴趣时继续往下看。

我没有传统前端开发背景。目标、内容结构、视觉方向、修改反馈和验收由我负责；Codex 等 AI Agent 承担大量代码实现、调试和测试。这篇文章记录的是我怎样判断 AI 的输出，并把想法推进成真实可运行的网站。

我负责目标、内容结构、视觉方向、修改反馈和验收

AI 协助代码实现、调试和测试

先做出一个能运行的版本

一开始，我先梳理项目顺序、内容字段、首页与详情页的关系，以及内容以后如何修改。7 月 29 日前，Codex 已根据这些需求搭出低保真首页和本地编辑器。这个版本并不好看，但我第一次能在浏览器里检查自己的内容结构，后续讨论也有了具体对象。

早期版本已经可以浏览和编辑项目，但视觉、层级和交互仍然很基础。

从生成结果到真实作品

能生成页面，
不等于做成网站

一键生成工具很适合拿来试方向。输入几句话，它就能拼出首屏、导航、按钮和卡片，几分钟内看起来已经像一个完整网站。下面两张图就是常见结果：渐变科技色、AI 人物或符号、悬浮数据卡，再配上一组放在哪里都说得通的文案。

这些网站乍一看很漂亮，但仔细看会发现华而不实：内容空洞、页面同质化，动画和显示效果也很僵硬。正是因为看到了这一点，我才决定做一套属于自己的动画效果。

浏览关系项目卡片、连续滚动和 FastNav 共享选中状态，切换时要保持同一条浏览线索。

页面衔接进入详情、返回首页和 About 展开分别处理动画与内容位置，不能套用同一个出现效果。

组件配合颜色、文字、图片和导航状态跟着项目变化，组件要一起工作，不能只把卡片摆整齐。

完成标准流畅度来自反复调整参数、修复问题、跑回归测试并设置冻结边界，不是第一次生成时自带的结果。

一键生成让我先有了一个页面。后面的时间主要花在让页面按照我的内容和浏览逻辑工作。AI 执行了大量代码，我负责判断哪里不对、该保留什么，以及什么时候可以验收。

功能有了，体验还是不对

低保真之后，我提高了对视觉和交互的要求。最初我主要用文字描述，得到的结果往往只是“功能存在”，实际体验却偏离目标。AI 会自行补全没有说清的部分，也容易落入常见的网站模板。

后来，我把当前页面、参考截图和交互视频放在一起比较，研究真正影响体验的差异，再限制改动范围，写清楚保留项、删除项和验收条件。需求由“做得像一点”变成了可以检查的具体要求。

  1. 01比较现状与参考
  2. 02找出关键差异
  3. 03限制改动范围
  4. 04写清验收条件

FastNav 和一个被删掉的功能

FastNav 是一次比较完整的纠偏。早期版本可以切换项目，但展开方式、卡片状态和滚动关系只能算近似。我结合截图、视频和实际页面，拆解它的输入、展开、选中反馈和离开行为，再让 Agent 按这些约束修改。研究记录和当前页面可以放在一起核对，结果不再依赖一句“看起来差不多”。

删除也是一次决策

另一处纠偏发生在 PreviewHero。Agent 增加了大型预览层，改变了原本的内容关系。我要求删除它，只保留背景、项目文字和缩略图轨道。这次修改有文字记录，但没有可公开核验的错误截图，因此不制作 Before/After。已经写完的功能并不一定值得保留。

项目变长以后，我开始写交接文档

随着页面、动画和内容增加，长对话开始变慢，新对话也很难理解旧决定。我要求生成 Handoff，记录当前状态、已完成内容和下一步。后来，交接文档继续加入冻结模块、验证集合、数据库与 Git 状态，以及新 Agent 的阅读顺序。

有了这些文件，换对话或换 Agent 时，就不用从头解释已经做过的决定。8 月 16 日，我把满意版本保存为 V3.0 冻结快照，后续只开放文章内容区，避免普通内容修改影响已经验收的首页、首屏和动效。

从进度记录到交接协议

聊天上下文　→　Handoff　→　新 Agent 可接手　→　冻结区与验证集合　→　持续推进

现在的网站，以及我真正完成的部分

现在的网站已有完整首页、项目切换、详情页、About 页面和内容管理入口。

早期原型当前网站

同一个项目从可运行的内容原型，逐步发展为现在的作品集网站。拖动中线可以比较两个阶段。

我仍然不能独立写出这套前端，也不把自己称为开发者。但我已经能把需求拆开，找到可以比较的证据，判断实现是否偏离目标，再让 AI 完成我无法单独执行的部分。

我的职责目标与内容结构视觉方向与修改反馈取舍、验收与冻结边界
AI 承担的大量执行代码实现调试与参数调整自动化测试与辅助检查

这件事改变了我怎么用 AI

这次经历改变了我使用 AI 的方式。遇到偏差时，我会确认问题发生在哪一层，补充证据，缩小范围，写清验收条件，并记录已经确认的决定。AI 负责大量执行，我仍要对目标、取舍和最终结果负责。
